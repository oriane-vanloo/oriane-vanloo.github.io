Rome2Rio · 2024–2025

Hitch 2.0 design system

Rome2Rio had two design systems and two dev stacks that had slowly drifted apart. I merged them into one, set up a clear path for components to follow and put tokens in place so that big changes, like swapping the typeface, became easy across both stacks.

Design systems Token architecture Cross-stack coordination

My role

Product Design Lead

Team

Engineering, product, brand

Outcome

95% adoption, 80% reduction in duplicates

The problem

Designers spent a lot of time hunting through Figma files for the right component while engineers had the same trouble finding things in code. Storybook had old and new versions side by side with no clear way to move from one to the other while the token names didn't match between our two stacks. Almost every new feature meant some rework which added up to a lot of lost time.

What I built

1
Single source of truth One Figma library to replace the two we had, with naming conventions checked against engineering. A component showcase at /design-system/hitch-2-0 shows how each component is used, with code snippets.
2
Token system OKLCH and APCP for colour as well as semantic tokens such as color.action.primary instead of raw values, so the intent behind a colour is captured and theming works the same way everywhere.
3
Graduation path Six steps: propose, validate, build, adopt, graduate, maintain. It works at any size, so anyone can tell where a component stands.
4
Documentation Storybook with every state documented, usage notes, do’s and don’ts, accessibility guidance and clear migration paths for anything we deprecate.

“We went from Roboto to Google Sans across the whole product in a day, with no rework.”

Changing the typeface

Rome2Rio wanted to feel more approachable so I made the case for replacing Roboto with a more human typeface. There was no budget and leadership had other priorities and they were worried about the extra space a new font takes up on the page. I told them the typeface carries the brand in every interaction and is easier to read and that we could design components with more white space in mind, which helps reading even more.

Once they were on board the tokens did the rest. Before Hitch this would have meant opening dozens of Figma files, updating each one by hand and coordinating across both stacks while hoping nothing broke. Because typography was already tokenised, I updated one token in Figma and every component using it followed. The switch to Google Sans took a day, and any future global change should be just as quick.

Getting people to use it

None of this matters if nobody uses it so a lot of my time goes into adoption. The six-step path means anyone can see where a component stands. Every component comes with guidance and do’s and don’ts. I look after Hitch across web, native and marketing which means decisions are made once and shared across the company.

Results

95% Design team now uses Hitch for component decisions
80% Reduction in duplicate component versions in 60 days
→ Dark mode, iOS and Android can now build on it
